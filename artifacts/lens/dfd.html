Data Flow Diagrams: L0 to L3

Four-level decomposition following Yourdon-DeMarco notation. L0 shows the system boundary and external entities. L1 to L3 decompose each major process into sub-processes with explicit data stores.

L0: Context Diagram

System boundary overview. Four external entities: Analyst (primary), Admin (reviewer), OpenAI API (NLP provider), and PostgreSQL (persistence). All data flows into and out of the central Lens Engine process.

flowchart LR Analyst["Analyst\nCX / HR / Ops"] Admin["Admin\nOptional Reviewer"] OpenAI["OpenAI API\nExternal NLP"] PG[("PostgreSQL\nAnalysis History")] Analyst -->|"Batch text + domain label"| P0(("P0\nLens\nEngine")) P0 -->|"Analysis dashboard"| Analyst Admin -->|"Browse analyses"| P0 P0 -->|"NLP prompts"| OpenAI OpenAI -->|"Scored results + themes"| P0 P0 -->|"Analysis result JSON"| PG PG -->|"Historical records"| P0

L1: Batch Ingestion & Validation

Decomposes P0 into 5 sub-processes covering upload acceptance, parsing, preview, labelling, and staging. Error path branches to P1.E which reports validation failures without writing any records.

flowchart LR An["Analyst\nBatch submitter"] DS1[("DS-1\nraw_batch_staging")] An -->|"CSV / pasted text"| P11(("P1.1\nAccept\nUpload")) P11 -->|"raw records"| P12(("P1.2\nParse &\nValidate")) P12 -->|"validated rows"| P13(("P1.3\nPreview\nRecords")) P13 -->|"5-row preview + count"| An P13 -->|"confirmed batch"| P14(("P1.4\nAssign\nLabel & Tag")) An -->|"source label + domain tag"| P14 P12 -->|"malformed rows"| PE(("P1.E\nFlag &\nReport Errors")) PE -->|"validation error report"| An P14 -->|"staged batch + metadata"| DS1

L2: NLP Pipeline Execution

Core pipeline decomposition. 7 sub-processes: prompt building, API call, response parsing, theme extraction, executive summary, anomaly detection, and result assembly. All OpenAI interactions are explicit bidirectional flows.

flowchart LR OpenAI["OpenAI API\nExternal NLP"] DS1[("DS-1\nraw_batch_staging")] DS2[("DS-2\nanalysis_results")] DS1 -->|"staged records"| P21(("P2.1\nBuild\nPrompts")) DS1 -->|"staged batch"| P24(("P2.4\nTheme\nExtraction")) P21 -->|"prompt array"| P22(("P2.2\nCall API\nSentiment")) P22 -->|"raw responses"| P23(("P2.3\nParse &\nScore")) P21 <-->|"prompts / responses"| OpenAI P22 <-->|"record batch / JSON"| OpenAI P24 -->|"theme context"| P25(("P2.5\nExecutive\nSummary")) P24 <-->|"theme prompt / themes"| OpenAI P25 <-->|"summary prompt / narrative"| OpenAI P23 -->|"scores array"| P26(("P2.6\nAnomaly\nDetection")) P23 -->|"scored records"| P27(("P2.7\nAssemble\nResult")) P24 -->|"theme list"| P27 P25 -->|"narrative"| P27 P26 -->|"anomaly flags"| P27 P27 -->|"assembled result JSON"| DS2

L3: Results Visualization & Storage

Four sub-processes: dashboard rendering, CSV export, history persistence, and history browsing. Both Analyst and Admin can browse history. Export is Analyst-only.
