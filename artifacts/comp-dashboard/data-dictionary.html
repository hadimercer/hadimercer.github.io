Comp Dashboard: Data Dictionary

Column-level definitions, data types, constraints, and plain-language business descriptions for all five tables in the TechNova Comp Benchmarking PostgreSQL schema.

Document
FRD-COMP-001 §8
Tables
5 tables
Project
Comp Dashboard
Author
Hadi Mercer
Database
PostgreSQL (Supabase)

employees

ColumnTypeDescription
employee_iduuidPrimary key. Unique identifier per employee record.
nametextEmployee full name. Used for display only; not used in benchmarking calculations.
job_familytextJob family category (e.g. Software Engineering, Finance). Links to job_soc_crosswalk for BLS mapping.
job_leveltextLevel within job family (e.g. L1 to L6). Used to filter internal grade bands.
office_locationtextCity or office name. Used to derive msa_code for geographic BLS wage data matching.
msa_codetextBureau of Labor Statistics Metropolitan Statistical Area code. Derived from office_location. Used in all BLS series ID construction.
base_salarynumericCurrent annual base salary in USD. Compared against BLS percentiles to compute gap $ and gap %.
created_attimestamptzRecord creation timestamp. Set on initial CSV upload.
updated_attimestamptzLast update timestamp. Refreshed on each upsert.

internal_job_grades

ColumnTypeDescription
grade_iduuidPrimary key.
job_familytextJob family. Composite key with job_level for grade band lookup.
job_leveltextLevel within family. Composite key with job_family.
band_minimumnumericBottom of the compensation band for this family/level. Displayed as internal reference in the benchmarking view.
band_midpointnumericTarget midpoint for the band. Used to compute compa-ratio and below-market flag (midpoint < BLS P25 triggers flag).
band_maximumnumericTop of the compensation band. Ceiling for merit increase guidance.
effective_datedateDate from which this band is active. Allows historical grade band tracking.

job_soc_crosswalk

ColumnTypeDescription
crosswalk_iduuidPrimary key.
job_familytextInternal job family name. Links to employees.job_family.
soc_codetextBLS Standard Occupational Classification code (e.g. 15-1252). Used to construct BLS series IDs for API calls.
soc_titletextOfficial BLS SOC title for the mapped occupation. Displayed in the dashboard for context.
match_qualitytextAnalyst-assigned match quality (Direct / Proxy / Approximate). Displayed as a transparency indicator in the benchmarking view.
pipeline_query_flagtextYES/NO flag. Only SOC codes marked YES are included in BLS pipeline API calls, controlling pipeline scope and API budget.

bls_wage_data

ColumnTypeDescription
wage_iduuidPrimary key.
soc_codetextSOC code from BLS API response. Foreign key to job_soc_crosswalk.
msa_codetextMSA code from BLS series ID. Matches employees.msa_code for geographic filtering.
data_typetextBLS data type code (e.g. 01=annual mean, 10=P10, 25=P25, 50=P50, 75=P75). Maps to wage percentile columns.
reference_yearintegerSurvey year from BLS response. Dashboard always displays the most recent year available (ORDER BY DESC LIMIT 1).
pct_25numericBLS 25th percentile annual wage for this SOC/MSA/year. Below-market flag triggers if internal band_midpoint < pct_25.
pct_50numericBLS median annual wage. Primary market benchmark reference point for gap calculations.
pct_75numericBLS 75th percentile annual wage. Used for above-market positioning assessment.
annual_meannumericBLS annual mean wage. Supplementary reference shown alongside percentiles.
pipeline_run_iduuidForeign key to pipeline_run_log. Links wage data to the pipeline run that produced it for auditability.

pipeline_run_log

ColumnTypeDescription
run_iduuidPrimary key.
run_typetextType of pipeline run: BLS_REFRESH or CSV_UPLOAD. Distinguishes external API runs from internal data uploads.
statustextRun outcome: SUCCESS, FAILED, or PARTIAL. Partial indicates some batches succeeded and some failed.
records_receivedintegerCount of records returned by API or present in CSV before validation.
records_writtenintegerCount of records successfully upserted. Discrepancy vs records_received is flagged per NFR-01b.
error_detailtextError message or batch-level warning. Null on SUCCESS runs.
run_attimestamptzTimestamp of pipeline execution start.
duration_secondsnumericTotal pipeline execution time. Used to track against OBJ-01 target of 2-minute complete refresh.
