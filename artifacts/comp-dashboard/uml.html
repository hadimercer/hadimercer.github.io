Flow A — BLS Market Data Pipeline

External market data ingestion (quarterly). Total Rewards Admin triggers a pipeline refresh; the BLS Pipeline reads SOC and MSA codes from the database, batches API calls in groups of 50, transforms and upserts wage data, then logs the run result.

sequenceDiagram autonumber actor Admin as Total Rewards Admin participant UI as Streamlit Dashboard participant PL as BLS Pipeline participant BLS as BLS Public API participant DB as PostgreSQL (Supabase) Admin->>UI: Clicks "Refresh BLS Data Now" UI->>PL: Calls pipeline.bls_pipeline.main() PL->>DB: Reads job_soc_crosswalk — get target SOC codes DB-->>PL: Returns SOC codes + pipeline_query_flag = YES PL->>DB: Reads employees — get MSA codes for office locations DB-->>PL: Returns distinct MSA codes Note over PL: Constructs BLS series IDs from SOC × MSA × data_type
Batches into groups of 50 (registered key limit) loop For each batch of ≤50 series IDs PL->>BLS: POST /timeseries/data/ — seriesid[], startyear, endyear BLS-->>PL: HTTP 200 — status, Results: series[] alt status = REQUEST_SUCCEEDED Note over PL: Parses wage values, maps data_type codes
Converts strings to numeric, handles suppressed as NULL else status = REQUEST_FAILED or empty Note over PL: Logs warning (FR-04)
Skips batch — no partial write (NFR-01a) else HTTP 429 — Rate limit PL->>DB: Writes FAILED to pipeline_run_log Note over PL: Preserves last-known-good dataset (NFR-03c) end end PL->>DB: Upserts rows INTO bls_wage_data ON CONFLICT DO UPDATE PL->>DB: Reconciles records_received vs records_written PL->>DB: Writes run summary to pipeline_run_log DB-->>UI: pipeline_run_log updated UI-->>Admin: Displays SUCCESS/FAILED status with record count

Flow B — CSV Internal Data Ingestion

Internal employee and job grade data upload path. Admin uploads a CSV; the system validates schema and data types before writing. On validation failure, no records are written (fail loudly — NFR-01a).

sequenceDiagram autonumber actor Admin as Total Rewards Admin participant UI as Streamlit Dashboard participant CSV as CSV Ingestion Module participant DB as PostgreSQL (Supabase) Admin->>UI: Uploads CSV file (Employee data or Job Grades) UI->>CSV: Passes DataFrame to validate_employees() or validate_job_grades() Note over CSV: Schema validation (FR-06)
Checks required columns, data types, non-null constraints alt Validation FAILS CSV-->>UI: Returns list of validation errors UI-->>Admin: Displays errors — no records written (NFR-01a) else Validation PASSES UI-->>Admin: "Validation passed — confirm load?" Admin->>UI: Clicks "Confirm and Load" UI->>CSV: Calls upsert_df(conn, df, UPSERT_SQL) loop For each row in validated DataFrame CSV->>DB: UPSERT ON CONFLICT DO UPDATE SET all fields end CSV->>DB: Writes run summary to pipeline_run_log DB-->>UI: Commit confirmed UI-->>Admin: Displays records written and duration end

Flow C — Dashboard Query (Read Path)

Read path from End User filter selection through to chart render. All queries cached via @st.cache_data(ttl=300). Target: complete benchmarking view render in under 2 minutes (OBJ-01).

sequenceDiagram autonumber actor User as End User (Recruiter / HRBP) participant UI as Streamlit Dashboard participant DB as PostgreSQL (Supabase) User->>UI: Selects Job Family + Level + Office Location UI->>DB: SELECT from internal_job_grades WHERE job_family=? AND job_level=? DB-->>UI: Returns band_minimum, band_midpoint, band_maximum UI->>DB: SELECT from job_soc_crosswalk WHERE job_family=? AND pipeline_query_flag=YES DB-->>UI: Returns soc_code, match_quality, soc_title UI->>DB: SELECT from employees WHERE office_location=? → MSA code DB-->>UI: Returns msa_code, msa_name UI->>DB: SELECT from bls_wage_data WHERE soc_code=? AND msa_code=? ORDER BY reference_year DESC LIMIT 1 DB-->>UI: Returns pct_25, pct_50, pct_75, annual_mean Note over UI: Computes gap $ and gap % vs BLS P50
Applies below-market flag if midpoint < P25
Renders grouped bar chart + KPI metrics UI-->>User: Benchmarking view — Internal vs Market Note over UI: All queries cached via @st.cache_data(ttl=300)
