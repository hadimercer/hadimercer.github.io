Schema Overview

The Cadence data dictionary defines every table, column, data type, constraint, and plain-language business definition across the four workflow modules. It is designed for developer handoff and stakeholder review: each entry explains not just the technical type but the business meaning and any design rationale for non-obvious decisions.

employees
Core employee record. Source of truth for headcount, job grading, location, and compa-ratio calculations across all workflows.
headcount_snapshots
Monthly point-in-time headcount records used for trend reporting in WF1. Stores KPI calculations at snapshot time.
performance_records
Weekly 1:1, monthly check-in, and quarterly review records from WF4. Pre-populates quarterly review forms.
comp_review_cycles
Merit cycle metadata. Tracks cycle status, budget pool allocations, and approval chain for WF2.
merit_recommendations
Manager merit % submissions per employee per cycle. Tracks budget compliance and approval status.
attrition_risk_scores
Daily composite risk scores per employee from WF3. Stores seven factor contributions and RAG classification.
risk_factor_config
Configurable weight table for the seven attrition risk factors. Allows HR to adjust model sensitivity without code changes.
pipeline_run_log
Audit trail for all pipeline executions. Records timestamp, status, record counts, and error detail.

The full data dictionary is available as a Word document on GitHub, with column-level type definitions, business descriptions, constraint notes, and design rationale for each table.
