Lens: open-text feedback, analyzed with guardrails

A text analysis workflow for survey comments and feedback: validate a batch, add business context, score sentiment and themes with an AI model, and store every run for comparison over time.

The HR problem

Engagement survey comments and exit feedback are collected at scale and read once. The scores from a survey get trended every cycle, but the comments rarely do, so there is no consistent way to compare what people said this cycle with what they said last time.

The analysis usually breaks down in one of three places: the text is messy, the reading has no business context, or the results are not stored in a way that allows comparison. Lens treats text analysis as a repeatable workflow instead of a one-off prompt. It is built for survey comments first and works for any open-text feedback, such as support notes or project feedback.

What I built

  • Upload a CSV file or paste text. Lens checks the encoding, finds the text and date columns, rejects empty rows, enforces a batch size limit and shows a five-row preview. No AI call happens until you confirm the batch.
  • Run the analysis: a sentiment score for every comment, the main themes, an executive summary, priority actions and unusual patterns, with a retry if the model returns malformed output.
  • Name a series, such as a quarterly engagement survey, so each new run is compared with the previous cycle and the summary reflects what changed.
  • Reopen any stored analysis later without calling the model again. Every run, record and pipeline log is saved to PostgreSQL.
  • Browse everything in Demo Mode with no API key: seeded analyses load from the database, and live runs sit behind an admin password.

Tour the demo

  1. The app opens in Demo Mode, with stored analyses and no sign-in.
  2. Start at Overview to see the workflow and which mode is running.
  3. Open the Analysis Library to browse stored runs by series, domain or date.
  4. Reopen any stored analysis to see the full dashboard without calling the model again.
  5. For a live run, request demo access and I will share the admin password.

How it works

Six stages take a batch from raw text to stored results. Each stage has defined inputs, outputs and failure modes, documented in the data flow diagram.

The pipeline

  1. Ingestion and validationEncoding check, text and date column detection, empty-row rejection, a five-row preview and a batch size limit.
  2. Context and seriesThe analyst adds a batch label, a domain tag and optional business context. If the batch belongs to a named series, the previous cycle is retrieved and added as context.
  3. Admin gate and confirmationIn Live Mode, a run needs the admin password and shows the expected model usage first. Demo Mode skips this stage.
  4. AI analysisSentiment for each record, then themes, a structured summary, key takeaways, priority actions and unusual patterns. Malformed output is retried.
  5. Saving resultsThe run, its records, its context and a pipeline log entry are saved to PostgreSQL, numbered within their series.
  6. Dashboard and historySummary, takeaways, actions, sentiment split, theme heatmap, flags, sentiment over time and comparison with the prior cycle.

Governance built in

Public access

Demo Mode

With no API key present, the app runs on seeded analyses. Anyone can review it without triggering a paid model call.

Live runs

Admin gate

Live analysis needs an admin password on the New Analysis page, and the expected model usage is shown before you confirm.

Cost and behavior

Model allowlist

Only models on an approved list can be selected, which keeps cost and output predictable.

Secrets

No keys exposed

API keys stay in the server’s secrets, never in the code or the browser.

What this shows

  • Using AI as a governed component inside a workflow, not a chat box.
  • Human review and business context before conclusions: the analyst checks the batch and adds context before any model call.
  • Cost and access controls designed in from the start: Demo Mode, the admin gate and the model allowlist were in the requirements before the first line of code.
  • Analysis over time: named series and stored runs make this cycle comparable with the last.

Limits

Lens is a personal project run on sample and synthetic text. It is not a production system.

AI sentiment is a starting point for a human reader, not a verdict. Comments from small groups can identify people, so a real deployment needs minimum group sizes and access rules.
