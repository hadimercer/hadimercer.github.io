The Problem

HR teams running manual workflows carry a hidden tax. A monthly headcount report takes hours of spreadsheet work. Merit reviews require someone to manually check six eligibility rules per employee. Performance conversations go undocumented and have to be reconstructed from memory at review time. And attrition risk — the signal that someone is about to leave — is only ever identified after they have already gone.

None of these problems is hard in isolation. What makes them costly is that they are solved separately, in different tools, by different people, with no shared data layer. Performance ratings that should influence merit eligibility live in one spreadsheet. Pay position data that should inform attrition risk lives in another.

Cadence treats the four HR workflows as a single connected system. Each workflow produces outputs that become inputs for the next. The result is not four tools — it is one platform where the work of each workflow compounds into better decisions in the next.

The Four Workflows

Workflow 1
Workforce Intelligence
Monthly headcount CSV ingestion with schema validation, KPI calculation, and pipeline run logging. Outputs: active count, attrition rate, compa-ratio by grade, headcount vs budget variance.
Workflow 2
Performance Management
Weekly 1:1 capture → monthly check-in tracking → quarterly review aggregation → formal performance rating. Ratings feed directly into merit eligibility and attrition scoring.
Workflow 3
Compensation Review
Six-gate eligibility engine → budget pool management → manager recommendation forms → HR approval workflow. Real-time budget utilisation tracking as recommendations are submitted.
Workflow 4
Attrition Risk
Seven-factor configurable scoring engine → RAG status → ranked risk register → retention action logging. Weights are adjustable by HR admins without a code change.

What It Does

  • Accepts monthly headcount CSV exports — validates against required column schema, reports row-level errors, persists validated records, and calculates computed columns (compa-ratio, headcount delta, new hire flag)
  • Captures weekly 1:1 records and monthly check-ins; auto-aggregates them into a quarterly review summary the manager edits, rates, and submits for HR approval
  • Runs the six-gate merit eligibility engine — active status, minimum tenure, no PIP, rating threshold, time since last increase, budget confirmed — and shows per-gate results per employee
  • Scores each active employee across seven attrition risk factors: compa-ratio position, rating trend, time since merit, time in role, sentiment signal from 1:1 notes, check-in frequency, and role market risk
  • Provides a configurable weight table for the attrition scoring engine — HR can tune factor weights via the UI without a developer, with every change written to an audit log
  • Connects analytically to the companion S2 Comp Dashboard — TechNova identifies which job families are below market; Cadence identifies which individuals in those roles score highest on attrition risk

What This Demonstrates

  • End-to-end business analysis: four workflows, each with a defined business problem, requirements document, and working implementation — 45 functional requirements across WF1–WF4
  • Cross-workflow data integration: performance ratings feed merit eligibility; headcount and pay data feed attrition risk scoring — the analytical dependencies are enforced by FK constraints in the schema
  • Rules-based decision engine design: the six-gate eligibility engine and seven-factor attrition scoring are documented as requirements before any code was written
  • Process improvement discipline: as-is process documented in BPMN before any solution was designed — 10 years of HR operations translated into formal process requirements
  • Data modelling: 13-table PostgreSQL schema designed to support audit trail integrity, process state management, and the analytical connections between workflows
  • BA framing of an operational domain — not an HR tool built by an HR professional, but a process solution designed by an analyst who happens to know the domain deeply

Data Flow Architecture

Workflows are built in dependency order: headcount first, then performance, then compensation review, then attrition risk. This reflects the actual data dependency chain — attrition risk scoring cannot produce meaningful output without headcount data, performance ratings, and pay position all present and structured.

Merit Eligibility Engine

Six sequential gates — an employee must pass all six to be eligible for the merit cycle. Each gate result is displayed individually, so managers can see exactly why an employee is ineligible and when they will next qualify.

FR ID Gate Condition
WF2-FR-004Gate 1 — Employment StatusEmployee must be in active status at the cycle open date
WF2-FR-005Gate 2 — Minimum TenureMust have completed the configured minimum months of employment
WF2-FR-006Gate 3 — No Active PIPMust not have an active performance improvement plan on record
WF2-FR-007Gate 4 — Rating ThresholdMost recent formal performance rating must meet or exceed the configured minimum
WF2-FR-008Gate 5 — Merit RecencyMinimum elapsed time since last merit increase must be satisfied

Attrition Risk Scoring Engine

Seven-factor scoring model with configurable weights. Each factor is scored independently, weighted, and summed to a composite risk score. Scores map to RAG status. The weight configuration is adjustable via the app — no code change required — with every configuration change audited.

FR ID Factor Signal
WF3-FR-002Compa-ratio positionPay relative to grade band midpoint — lower compa-ratio = higher risk
WF3-FR-003Rating trendPerformance rating direction over rolling window — declining trend = higher risk
WF3-FR-004Time since meritElapsed months since last merit increase — longer elapsed = higher risk
WF3-FR-005Time in roleTenure in current position — plateau signal combined with other factors
WF3-FR-006Sentiment signalConcern flags and tone in weekly 1:1 notes — negative pattern = higher risk
WF3-FR-007Check-in frequencyCompliance rate for monthly check-ins — low compliance = disengagement signal
WF3-FR-008Role market riskManually flagged indicator for high-demand roles where external pull is elevated

BA Process

Problem Discovery

The starting point was not "build an HR system." It was observing that most HR operational work fails at the data handoff — not at the task itself. A performance rating is completed correctly but never makes it into the merit eligibility calculation. A headcount figure is accurate in the HRIS but has to be re-extracted manually for every reporting cycle. The analytical question driving this project was: what is the minimum data architecture that would allow these four workflows to talk to each other?

Stakeholder Personas

Persona Core Frustration Requirements Driven

Scope Decisions

Decision Rationale Future Phase
Rules-based scoring over ML modelA rules engine is auditable, configurable without engineering support, and produces explainable outputs. Predictive models require historical resignation data that most mid-market organisations lack in structured formPhase 2 — once 12+ months of structured data exists
No role-scoped views in v1The data architecture supports it (every record carries employee ID and manager ID) but auth and authorisation adds risk without proportionate value before core workflows are validatedPhase 1 Polish
No HRIS direct integrationCSV upload provides the same structured input without integration complexity; removes dependency on HRIS API availability and auth for a portfolio demonstrationPhase 3 Scale

Design Decision — Build Order

The four workflows were built in dependency order: headcount first, then performance management, then compensation review, then attrition risk. This was not a convenience decision — it reflects the actual data dependency chain. Attrition risk scoring cannot produce meaningful output without headcount data, performance ratings, and pay position all present. Building in this order kept the data model honest and prevented shortcuts that would have required later refactoring.

Cross-Portfolio Connection

Cadence (S1) and the Comp Dashboard (S2) are analytically connected. S2 operates at role level — identifying which job families are below the BLS market benchmark. Cadence operates at employee level — identifying which individuals in those underpaid roles score highest on attrition risk. Together they answer the question a CHRO actually asks: which people are we most likely to lose, and is compensation the reason?
